# Security and privacy reporting

Fishing Intelligence handles data that can reveal private fishing locations, trip history and user operating constraints.

Please do not publish real private marks, credentials, access tokens, connected-store identifiers or personal trip records in public issue reports. Prefer a minimal synthetic reproduction.

Security-sensitive reports should use the repository host's private security-reporting mechanism when available, or the publisher's current private support channel. Do not post exploit details publicly before a fix can be assessed.

The core plugin does not claim secure multi-user ACL enforcement, remote revocation of exported copies, background geofencing or binary attachment metadata scrubbing.
